# Step 3 中文说明：程序怎样画趋势线

## 怎样运行

先把更新包中的文件按相同路径放入完整项目，替换旧文件。更新包本身不包含全部输入数据，不能单独运行。打开终端，进入包含 app.py 的 swingpoints_project 文件夹，激活已有 Python 环境，然后执行：

```bash
source .venv/bin/activate
python app.py data/data.csv --output output/step3
```

如果使用 Windows，请沿用 README 中的环境命令。原来环境能运行程序的话，这次不用安装新的软件包。

运行后打开 `output/step3/prices.png`，就能看到价格、摆动点和趋势线。
如果想打开可以操作的桌面窗口：

```bash
python app.py --gui data/data.csv
```

## 先理解两个概念

**上升趋势线**：连接逐渐抬高的低点。例如，先出现一个低点 100，再出现低点 102，连接它们就得到一条向上的线。

**下降趋势线**：连接逐渐降低的高点。例如，先出现高点 110，再出现高点 108，连接它们就得到一条向下的线。

不是随便找两个点就算成功。程序还要检查它们之间及确认等待期间的价格，有没有已经穿过这条线。

## 程序的具体顺序

1. **读取数据**：支持 CSV 和 JSON，按时间排序并检查价格是否有效。
2. **找已确认的摆动点**：沿用 Step 2。默认前后各比较 2 条数据，所以一个低点/高点出现后，还要等 2 条数据才能确认。
3. **尝试连接**：每次有新低点，尝试连接前面最多 20 个低点；第二个低点必须更高。新高点则与前面的高点连接，第二个必须更低。“20”是摆动点数量，不是分钟数。
4. **算直线**：两个点确定一条线。价格差除以分钟差就是斜率。中间有时间缺口时，使用实际经过的分钟数。
5. **排除不合格的线**：上升线形成前，如果价格已经明显低于它，就不采用；下降线相反。默认允许的误差是第一个点价格的 0.5%，每条线的这个金额固定。
6. **确认这条线可用的时间**：必须等第二个锚点被 Step 2 确认，不能把“后来才发现的线”当成过去已经知道的东西。
7. **数接触点**：后续或两锚点之间的同类摆动点，接近直线就算一次接触；每个点只能算一次，也必须已经确认。两个锚点本身也算接触。
8. **记录终止时间**：上升线被价格向下穿过、或下降线被向上穿过，且超过容差后，就标记 broken 并停止延长。断掉的旧线不会恢复，但之后可以产生新线。
9. **筛选绘图**：默认每个方向最多显示 3 条。优先选接触点多的，然后选两锚点时间间隔长的，再选确认较新的。共享至少两个接触点的线会被去重。所有合格候选线仍会导出到表格。

这里的“显著摆动点”用 Step 2 的窗口规则来定义。把 Window 从 2 调到 5，会用更大的范围判断局部高低点。没有单独设置涨跌幅门槛，因此自动结果不会与老师手画的每条线完全一样。

## 用数字算一次

| 时间 | 已经出现的低点价格 |
| --- | ---: |
| 10:00 | 100 |
| 10:02 | 102 |
| 10:04 | 104 |

先连接前两个低点：斜率 = (102 - 100) / 2 = 每分钟上涨 1。
因此线在 10:04 的高度应该是 104。第三个低点正好是 104，等它确认后，就多了一次接触。

如果窗口是 1，10:02 的低点要等 10:03 才确认，这条线也从 10:03 才可用。
10:04 的第三个低点，则到 10:05 才能增加接触次数。

默认容差为第一个点 100 的 0.5%，即 0.5。
10:06 时线的高度是 106，如果 Close 严格低于 105.5，Close 模式就把这条线标记为 broken。
正好等于 105.5 仍在允许范围内。下降线的计算方向相反。

## 图应该怎么看

- **绿色线**：上升支撑线。
- **红色线**：下降阻力线。
- **虚线**：回头连接历史锚点的部分，当时还没有足够信息确认这条线。
- **菱形**：第二个锚点确认、这条线开始可用的时间。
- **实线**：确认以后，在已观察数据中的延伸部分。
- **大 X**：第一次超过容差穿线的位置，线到这里停止。
- 原来的三角形和小 x 仍分别表示摆动点位置和摆动点确认时间。

图中既可能有 active 线，也可能有已经 broken 的历史线；排名靠前不等于最新。
显示更多历史时，接触次数和排名可能变化。要看当时知道什么，请设置 Observed bars，或使用 --until。

## Close 和 High–Low 的区别

默认 `close`：低点、高点和穿线检查都使用 Close，与原来的折线分析保持一致。
`high-low`：上升线用 Low 的低点，并检查 Low 有没有向下穿线；下降线用 High 的高点，并检查 High 有没有向上穿线。

```bash
python app.py data/data.csv --basis high-low --window 5 --output output/step3_wicks
```

## 代码分别放在哪里

| 文件 | 工作 |
| --- | --- |
| app.py | 调用读取 → 摆动点 → 趋势线 → 绘图 → 导出 |
| swingpoints/trendlines.py | 新增的核心算法，判断线是否合格、接触次数和终止时间 |
| swingpoints/plotting.py | 将选中的线画到原来的价格图上 |
| swingpoints/gui.py | 新增参数输入和 Displayed trendlines 表格 |
| swingpoints/output.py | 新增 trendlines.csv 和 trendlines.json 输出 |
| tests/test_trendlines.py | 自动检查新的算法和输入/输出流程 |

新增代码都使用三引号注释说明 Args、Result 和 Exception。
Step 1 的数据读取和 Step 2 的摆动点算法没有改变。

## 怎样检查结果

```bash
python -m unittest discover -s tests -v
```

测试包括手工计算的上下趋势线、误差边界、未确认摆动点、穿线、时间缺口、CSV/JSON 一致性和全部历史截点回放。

这一步是确定规则后计算和绘图，没有使用 Logistic Regression、LightGBM 或 LSTM，也没有预测下一分钟价格。接触次数只是选线依据，不是成功概率。
